# Q&A: ภาพเล่าเหตุการณ์สอดคล้องกับโจทย์ NF-01 อย่างไร

## คำถาม

[https://github.com/aekanun2020/2026-Digital-Forensic/blob/main/student/agentic-siem/images/README.md](https://github.com/aekanun2020/2026-Digital-Forensic/blob/main/student/agentic-siem/images/README.md)&#x20;

อันนี้คิดว่างัยครับ มันสอดคล้องกับโจทย์ตรงไหนอย่างไรบ้าง

## คำตอบของ Codex

**อันนี้ตรงกับโจทย์ NF-01 โดยตรงครับ** เพราะใช้เครื่อง `10.70.0.66` และไฟล์ F1–F6 ชุดเดียวกับที่โจทย์ระบุ เหมาะเป็น **ภาพประกอบเฉลยของกรณีนี้** มากกว่าภาพพื้นฐานทั่วไป

ผมตรวจทั้ง [README และภาพจริง](https://github.com/aekanun2020/2026-Digital-Forensic/blob/main/student/agentic-siem/images/README.md) แล้วเทียบกับโจทย์และคำตอบ cross-check ที่บันทึกไว้ การประเมินนี้ไม่ได้รันตรวจ raw files ใหม่ครับ

| คำถามในโจทย์ | ภาพสอดคล้องอย่างไร | ส่วนที่ภาพยังให้ไม่ครบ |
|---|---|---|
| **1. ติดต่อใคร ใครเริ่ม ใช้ port/protocol และมีการตอบกลับหรือไม่** | แสดง `.66` ติดต่อ DNS `10.70.0.53`, ภายนอก `203.0.113.66:443` และเครื่องภายในผ่าน 22/445/3389 | ยังไม่แสดงข้อมูลตอบกลับและ TCP handshake ครบ รวมถึงรายชื่อเครื่องภายใน `.1–.25` |
| **2. ลำดับเวลา จำนวน ความถี่ และระยะเวลา** | สามช่วงตรงกับผลตรวจ: DNS 120 ครั้งทุก 60 วินาที → outbound 120 connections → ภายใน 25 connections | ควรเติมช่วงห่าง 10 วินาทีของสองช่วงหลัง และแยกเวลาเริ่มครั้งสุดท้ายออกจากเวลาจบ packet สุดท้าย |
| **3. ส่งออก/รับกลับกี่ bytes และ payload บอกอะไร** | ขาออก **6,010,330 bytes** และ HTTP plaintext บน port 443 ตรงกับ cross-check | ยังขาดขากลับ **240 bytes** และคำอธิบายว่าเป็น TCP payload: body 6,000,000 + ส่วนคำขอ/headers 10,330 bytes |
| **4. ติดต่อภายในอย่างไร สำเร็จระดับใด** | 25 เครื่อง ผ่าน 22/445/3389 และข้อความว่าเป็น remote-service probe ตรงกับผลตรวจ | ยังขาดรายละเอียดว่าแต่ละคู่มี probe 35 bytes และตอบ `OK` 2 bytes โดยยังไม่ยืนยัน authentication หรือรันคำสั่ง |
| **5. อะไรยืนยันได้ อะไรเป็นสมมติฐาน** | มีข้อความกำกับว่าไม่ยืนยันการควบคุมเครื่อง การขโมยข้อมูล หรือการยึดเครื่อง และระบุว่า F6 เป็นข้อมูลจำลอง | ภาพไม่มี record/packet locators จึงต้องอ่านประกอบตารางหลักฐาน |

รายละเอียดที่ใช้เทียบอยู่ใน [cross-check หมวด 2–6 และตารางข้อสรุป](https://github.com/aekanun2020/2026-Network-Forensics/blob/main/cases/01-investigate-10.70.0.66/CROSS-CHECK-NF-01-v2.md)

**มีสองจุดในภาพจริงที่ควรแก้ก่อนนำไปใช้**

1. **ช่อง DNS เขียนว่า `DNS server: 203.0.113.66` ผิดบทบาท**  
   ต้องเป็น `DNS answer: 203.0.113.66` เพราะ DNS server ที่ `.66` ติดต่อคือ `10.70.0.53` ส่วน README เขียนว่า DNS answer ถูกแล้ว หลักฐานอ้างอิงคือ F2 records #1–120 และ F1 packets #1–240

2. **ป้ายรหัสหลักฐานช่อง Outbound เป็น `[F3, F3, F4, F5]`**  
   ต้องเป็น **`[F1, F3, F4, F5]`** ให้ตรงกับข้อความ PCAP และรายการใน README

อีกจุดที่ควรทำให้แม่นขึ้นคือ “ภายใน 240 วินาที”: ตัวเลขนี้ตรงกับ **เวลาเริ่มครั้งแรกถึงเวลาเริ่มครั้งสุดท้าย** ส่วนถึง packet สุดท้ายคือ **240.006 วินาที** ตาม [ตารางลำดับเวลาใน cross-check](https://github.com/aekanun2020/2026-Network-Forensics/blob/main/cases/01-investigate-10.70.0.66/CROSS-CHECK-NF-01-v2.md)

ผมเห็นว่า **ควรวางภาพนี้ในส่วนเฉลย เปิดหลังผู้เรียนส่งคำตอบแล้ว** เพราะภาพเปิดเผยโดเมน คู่ติดต่อ จำนวนครั้ง ปริมาณ และสามช่วงพฤติกรรมเกือบทั้งหมด หากแนบให้ agent ก่อนสืบสวน จะชี้นำคำตอบและไม่สอดคล้องกับ [โจทย์ NF-01-v2 ที่ให้ค้นจาก raw evidence โดยไม่กำหนดผลไว้ล่วงหน้า](https://github.com/aekanun2020/2026-Network-Forensics/blob/main/cases/01-investigate-10.70.0.66/QUESTION.md) ครับ
