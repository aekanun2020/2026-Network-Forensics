# หลักฐานประกอบคำตอบ MCP — 8 กันยายน 2026

[คำตอบฉบับอ่านบน GitHub](../../AGENT-ANSWER-MCP-2026-09-08.md) · [ต้นฉบับคำตอบตรงตามข้อความในบทสนทนา](../agent-answer-mcp-2026-09-08-original.txt) · [สารบัญเคส](../../README.md)

นี่เป็นการเก็บผลที่เกิดระหว่างการสืบสวนในบทสนทนา ไม่ใช่ผลรันใหม่ในขั้นตอนจัดเก็บ ผู้วินิจฉัยคือ Codex; Python ใช้จัดข้อมูลและตรวจความเท่ากันเชิงกำหนดแน่นอน ไม่มี external LLM judge และไม่มี Spark/PySpark job

[โจทย์ที่ได้รับจริง](question-original.txt) มีคำถามและ virtual paths หกไฟล์ แต่ไม่มี QUESTION.md ฉบับเต็มและตาราง hashes อ้างอิง ผู้ใช้ระบุ [endpoint เพิ่มเติม](endpoint-messages.json) ภายหลัง จึงแยกขอบเขตนี้จากการทดสอบ NF-01-v2 ที่กำหนดให้ส่งทั้งหน้า คำตอบถูกส่งก่อนการเทียบเฉลย แต่ SHA-256 ของข้อความคำนวณในขั้นตอนจัดเก็บภายหลัง ไม่อ้างการตรึง hash ก่อนตรวจ

ไฟล์ F1–F6 หมายถึง raw หกไฟล์ตามโจทย์ โดย [manifest](manifest.json) มี virtual/physical paths, bytes และ SHA-256 ผลจาก MCP ใช้เลขบรรทัดและ packet จาก raw ต้นทาง ไม่ใช้เลขแถวหลังกรองแทน locator

ผล `F*-src/dst/scope` เป็นการสแกนทั้งไฟล์ ส่วน `F*-lines-*` และ `F1-packets-*` เป็นหลักฐานที่อ่านเป็นหน้า F1-packets รวม 1,255 packets ของเป้าหมาย และ F1-remaining ตรวจส่วนถัดไป ผล `F1-body-repeated` ตรวจรูปแบบกับ payload เต็ม แม้ข้อความตัวอย่างจากเครื่องมือจำกัดความยาว

เก็บทั้งผลสำเร็จและ error outputs ที่ยังอยู่ในโฟลเดอร์ทำงาน เช่นข้อจำกัด limit ของ PCAP และ aggregation fields ของ F6 ตามด้วยผล fixed; `*-jobs.json` เป็น batch requests ที่บันทึกไว้ คอลเลกชันนี้ไม่ใช่ transcript ครบทุกคำสั่ง และไม่สร้าง trace ของผลที่ไม่ได้เก็บไว้ย้อนหลัง ไม่คัดลอก credentials, MCP session headers หรือ client script ที่ฝัง session identifier

[verification.json](verification.json) เป็นผลตรวจความเท่ากันของ records/packets เดิม ไม่ใช่คะแนนเทียบเฉลย [checks.py](checks.py) เก็บโค้ดตามที่ใช้เดิมและยังอ้างโฟลเดอร์ชั่วคราวเดิม จึงไม่ใช่โปรแกรมตรวจซ้ำจาก ZIP แบบ standalone ข้อมูลที่คัดลอกมี hashes ใน [provenance.json](provenance.json)
